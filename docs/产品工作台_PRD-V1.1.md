> 版本：V1.1（前后端分离版）\
> 状态：需求基线\
> 日期：2026-09-22\
> 正式域名：`workbench.celiawang.top`\

## 1. 项目概述

产品工作台是一套面向产品、研发和测试团队的在线协作系统，用于集中管理需求、任务、平台、人员、分派关系、时间节点和站内通知。

### 1.1 产品目标

1. 建立统一的需求池和任务台账。
2. 让团队快速识别本周重点、临期、逾期和阻塞事项。
3. 支持“一个负责人、多个参与人”的协作方式。
4. 串联需求收集、任务拆分、人员分派、进度跟踪和上线归档。
5. 通过权限和操作记录保证关键变更可追溯。
6. 支持正式线上发布，PC 优先，并适配移动浏览器。

### 1.2 用户角色

岗位角色：产品、研发、测试。

操作权限：管理员、普通成员。岗位与操作权限相互独立。

| 用户 | 主要诉求 |
| --- | --- |
| 产品 | 收集需求、拆分任务、分派人员、跟踪上线 |
| 研发 | 查看和更新负责或参与的任务与里程碑 |
| 测试 | 跟踪测试事项、更新状态和阻塞信息 |
| 管理员 | 管理平台、人员、字典、全部数据和归档恢复 |

## 4. 核心规则

### 4.1 需求与任务关系

1. 一个需求可关联零个或多个任务。
2. 一个任务最多关联一个需求。
3. 任务可以不关联需求而独立存在。
4. 从需求详情创建任务时，默认带入需求及平台。
5. 归档需求不自动归档关联任务，历史关系保留。

### 4.2 分派

1. 每条需求或任务最多一名负责人。
2. 每条需求或任务可有多名参与人。
3. 分派变化产生站内通知和操作记录。
4. 停用成员不能被新增为负责人或参与人。

### 4.3 编号

- 需求：`REQ-YYYYMM-序号`，例如 `REQ-202609-001`
- 任务：`TASK-YYYYMM-序号`，例如 `TASK-202609-001`
- 编号由系统生成、全局唯一、不可修改；序号每月从 `001` 开始

### 4.4 优先级

| 优先级 | 定义 |
| --- | --- |
| P1 | 重要且紧急 |
| P2 | 重要但不紧急 |
| P3 | 不重要但紧急 |
| P4 | 不重要且不紧急 |

### 4.5 状态

需求状态：`待评估`、`设计中`、`研发中`、`测试中`、`已上线`。

任务状态：`待处理`、`进行中`、`阻塞`、`已完成`、`挂起`。

规则：

1. V1 允许状态跳转和退回，不强制线性流转。
2. 每次变更记录操作人、时间、原状态和新状态。
3. 需求切为已上线时自动记录实际上线时间，管理员可修正。
4. 任务切为已完成时自动记录实际完成时间。
5. 已完成任务重新打开时，清空当前完成时间，但历史记录保留。
6. 挂起任务暂停逾期提醒，阻塞任务不暂停。

### 4.6 本周重点

本周指周一 00:00 至周日 23:59，时区为 Asia/Shanghai。

手动纳入：有编辑权限的成员勾选“本周重点关注”，显示 `手动重点` 标签，直到人工取消。

需求自动纳入条件：

- 目标上线时间落在本周
- 目标上线时间已逾期，且需求未上线

任务自动纳入条件：

- 开始时间落在本周
- 最终截止时间落在本周
- 未完成里程碑的计划完成时间落在本周
- 最终截止或未完成里程碑已逾期，且任务未完成、未挂起

自动纳入显示 `本周节点` 标签。同时命中手动与自动条件时显示两个标签，事项只展示一次。

## 5. 功能需求

### 5.1 账号与登录

1. 不开放注册，由管理员创建用户名和临时密码。
2. 首次登录或密码重置后强制修改密码。
3. 账号状态包括启用和停用；停用账号不能登录。
4. 管理员可重置密码，历史分派和操作记录不随账号停用而删除。
5. 密码必须安全哈希存储，不得明文保存。

### 5.2 工作台

数据概览：需求总数、任务总数、进行中数量、阻塞数量。统计默认排除归档数据。

本周重点：分区展示重点需求和重点任务，至少显示编号、名称、平台、状态、优先级、负责人、关键日期和纳入标签。

临期逾期：

- 展示未来 3 天内到期的目标上线、最终截止和里程碑
- 展示所有已逾期未完成事项及逾期天数
- 挂起任务不进入逾期区域，阻塞任务仍展示

我的工作：我负责、我参与、分派给我但尚未完成的事项。

### 5.3 需求池

列表能力：表格/状态看板切换、分页、关键字搜索、筛选、排序、查看详情、归档数据查询。

筛选条件：平台、状态、类型、优先级、来源、负责人、本周标签。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 需求编号 | 系统 | 自动生成、只读 |
| 平台 | 是 | 从启用平台单选 |
| 需求名称 | 是 | 单行文本 |
| 需求描述 | 否 | 多行文本 |
| 需求类型 | 否 | 管理员维护，如优化、新功能 |
| 需求状态 | 是 | 固定状态选项 |
| 优先级 | 是 | P1-P4 |
| 需求来源 | 否 | 管理员维护 |
| 本周重点关注 | 否 | 默认否 |
| 提出人 | 否 | 文本，可记录内部或外部提出者 |
| 提出时间 | 否 | 日期时间 |
| 负责人 | 否 | 启用成员单选 |
| 参与人 | 否 | 启用成员多选 |
| 目标上线时间 | 否 | 用于自动纳入和提醒 |
| 实际上线时间 | 系统/管理员 | 已上线时自动记录 |
| 备注 | 否 | 多行文本 |
| 附件 | 否 | 多个附件 |
| 创建人、创建时间、更新时间 | 系统 | 只读 |
| 归档状态 | 系统 | 默认未归档 |

需求详情包括基础信息、人员、关联任务、附件、操作时间线，以及编辑、创建关联任务、归档入口。

### 5.4 任务管理

列表能力：表格/状态看板切换、分页、搜索、筛选、排序、查看详情、归档数据查询。

筛选条件：平台、关联需求、状态、优先级、来源、负责人、参与人、本周标签、独立/关联任务。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 任务编号 | 系统 | 自动生成、只读 |
| 平台 | 是 | 从启用平台单选 |
| 关联需求 | 否 | 为空时为独立任务 |
| 事项名称 | 是 | 单行文本 |
| 事项描述 | 否 | 多行文本 |
| 状态 | 是 | 固定任务状态 |
| 优先级 | 是 | P1-P4 |
| 来源 | 否 | 管理员维护，如产品、研发、售后 |
| 本周重点关注 | 否 | 默认否 |
| 负责人 | 否 | 启用成员单选 |
| 参与人 | 否 | 启用成员多选 |
| 开始时间 | 否 | 日期时间 |
| 最终截止时间 | 否 | 用于自动纳入和提醒 |
| 实际完成时间 | 系统 | 已完成时自动记录 |
| 里程碑 | 否 | 可添加多个 |
| 备注 | 否 | 多行文本 |
| 附件 | 否 | 多个附件 |
| 创建人、创建时间、更新时间 | 系统 | 只读 |
| 归档状态 | 系统 | 默认未归档 |

每个里程碑包含里程碑名称、计划完成时间、完成状态和实际完成时间。名称与计划完成时间必填；完成或取消完成均写入操作记录。

### 5.5 平台管理

字段：平台名称、说明、启用状态、排序值。名称必填且不可重复。

仅管理员可管理。已被引用的平台不得物理删除，只能停用；停用项不出现在新建表单，历史数据仍显示原值。

### 5.6 人员管理

字段：姓名、登录用户名、岗位、操作权限、账号状态、是否首次登录。

仅管理员可创建、编辑、停用账号和重置密码。账号停用前提示该成员负责的未完成事项数量，不自动转移负责人。

### 5.7 字典管理

管理员维护需求类型、需求来源和任务来源。字典项包含名称、启用状态和排序值。

被引用的字典项不能物理删除，只能停用。状态和优先级不是可配置字典。

### 5.8 通知中心

触发事件：

- 成为或移出负责人/参与人
- 负责人变化
- 状态变化
- 目标上线、最终截止或里程碑时间变化
- 距到期 3 天、到期当天、逾期

通知发送给负责人和参与人，临期逾期无负责人时发送给创建人。支持全部/未读筛选、单条已读、全部已读和跳转详情。同一事项同日的持续逾期提醒合并。

### 5.9 附件与操作记录

需求和任务支持多个附件。有详情权限的成员可查看；有编辑权限者可上传。上传、删除均写入操作记录。

必须记录创建、字段修改、状态、分派、时间、里程碑、附件、归档、恢复及管理员修正时间。记录至少包括操作人、时间、类型、字段、变更前值和变更后值，不允许普通用户修改或删除。

### 5.10 归档

1. 不提供业务数据物理删除入口。
2. 仅管理员可归档和恢复，操作需二次确认。
3. 归档数据不参与默认列表、统计、提醒和本周重点。
4. 归档数据可查询并保留详情、关联和操作记录。

## 6. 权限

团队数据默认透明，所有成员可查看团队内的需求、任务和操作记录。

| 操作 | 管理员 | 创建人 | 负责人 | 参与人 | 其他成员 |
| --- | --- | --- | --- | --- | --- |
| 查看团队数据 | 是 | 是 | 是 | 是 | 是 |
| 创建需求/任务 | 是 | 是 | 是 | 是 | 是 |
| 编辑全部业务字段 | 是 | 是 | 是 | 否 | 否 |
| 更新状态 | 是 | 是 | 是 | 是 | 否 |
| 更新里程碑、备注、附件 | 是 | 是 | 是 | 是 | 否 |
| 修改负责人/参与人 | 是 | 是 | 是 | 否 | 否 |
| 归档/恢复 | 是 | 否 | 否 | 否 | 否 |
| 管理平台、人员、字典 | 是 | 否 | 否 | 否 | 否 |

同一用户具备多个关系时取最高权限。权限必须由后端接口校验，不能只通过隐藏前端按钮实现。

## 7. 视觉与响应式

1. 采用蓝色主色的克制、紧凑企业工作台风格，建议主色 `#2563EB`。
2. 白、浅灰、深灰构成基础界面；红、橙、绿表达异常、临期和完成。
3. PC 使用侧边或顶部导航、紧凑表格、筛选区和清晰主操作。
4. 移动端将表格转为信息列表，表单使用全屏页面或全屏抽屉。
5. 移动端至少支持查看、搜索、筛选、新建、编辑、分派和状态流转。

## 8. 前后端分离架构约束

### 8.1 开发方式

1. 前端作为独立 Web 工程开发构建，通过 HTTP API 获取数据，不直接访问数据库。
2. 后端作为独立 API 服务，负责认证、权限、业务规则、数据持久化、定时提醒和附件鉴权。
3. 前后端以 OpenAPI 作为接口契约，统一路径、参数、响应、分页、错误码和鉴权。
4. 后端完成前，前端使用与接口契约一致的 Mock 数据完成页面、交互和响应式验收。
5. Mock 请求与真实请求共用 TypeScript 类型和调用入口，通过环境配置切换。
6. 前端先完成登录、工作台、需求池、任务、通知及管理页面，再按已确认页面冻结接口。
7. 生产环境建议同域访问：前端使用根路径，后端统一使用 `/api` 前缀。
8. 前后端可独立构建、测试和发布；接口变更必须同步更新 OpenAPI 和前端类型。

### 8.2 推荐技术方向

- 前端：React、TypeScript、Vite、Ant Design、TanStack Query、Mock Service Worker
- 后端：独立 REST API 服务；具体语言框架可在开发前单独确定
- 数据库：PostgreSQL 或 MySQL 8 均可，按团队维护经验最终选择
- 部署：Docker Compose，反向代理、前端、API、数据库分容器运行

## 9. 非功能需求

### 9.1 性能

- 列表使用服务端分页
- 正常网络下主要页面 3 秒内可用
- 常用查询响应目标 1 秒内，大文件上传除外
- 为状态、负责人、平台和时间等常用筛选字段建立索引

### 9.2 安全

- 全站 HTTPS，数据库不直接暴露公网
- 密码哈希、敏感配置使用环境变量
- 上传文件校验大小、扩展名和内容类型，并鉴权访问
- 登录限流、会话过期、CSRF、注入和越权防护
- 登录、账号、密码重置和高权限操作需审计

### 9.3 兼容与时间

- 支持主流 Chrome、Edge、Safari
- PC 重点适配 1280、1366、1440、1920 像素宽度
- 移动端重点适配 375 至 430 像素宽度
- 业务时区统一为 Asia/Shanghai

### 9.4 备份

- 数据库和附件每日备份
- 建议保留 7 个日备份和 4 个周备份
- 至少一份服务器外备份
- 上线前完成备份恢复演练

## 10. 核心验收标准

1. 管理员可创建不同岗位和权限的账号，首次登录强制改密。
2. 普通成员不能通过页面或直接请求绕过管理权限。
3. 必填字段缺失时无法提交，并准确定位字段。
4. 需求可关联多个任务，任务也可独立存在。
5. 每条事项只允许一个负责人，支持多个参与人。
6. 编号自动生成且不重复。
7. 状态跳转、退回及里程碑操作均可追溯。
8. 手动重点与系统自动纳入显示正确标签，同时命中不重复展示。
9. 提前 3 天、到期当天和逾期通知正确触发。
10. 挂起任务暂停逾期提醒，阻塞任务仍保留提醒。
11. 被引用的平台和字典项只能停用，历史数据显示正常。
12. 归档数据不参与默认统计和提醒，但可查询恢复。
13. 375 像素宽度下可完成核心查看和编辑流程。

## 11. 上线条件

部署前需确认：
