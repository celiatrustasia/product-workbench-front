# 迭代管理与免登录演示

## 迭代管理

入口在任务管理下方。一个迭代围绕目标和起止日期组织需求、任务，包含一位负责人、状态和完成进度。

1. 新建迭代，填写名称、开始日期、结束日期、负责人，可补充目标。两个日期分别使用单月日历选择，结束日期不能早于开始日期，可选择同一天。
2. 进入详情，批量移入需求、任务；已属于其他迭代的事项会转移到当前迭代。每项只属于一个迭代。
3. 开始迭代，按事项状态跟踪进度。未归档需求、任务计入总数；已上线需求和已完成任务计为完成。
4. 可选中事项移出或移至其他迭代。也可通过需求、任务表单修改归属，在列表更多筛选中按迭代查看。
5. 完成迭代不会将未完成事项改成完成，也不会自动结转；未完成事项保留，重新打开后可重新安排。
6. 删除迭代会保留需求、任务，只解除归属。

所有团队成员可查看和新建迭代。管理员、迭代创建人或负责人可编辑、开始、完成、重新打开、删除及编排迭代。移动事项还需要该事项的基础编辑权限；跨迭代移动需能管理源、目标迭代。完成后的范围锁定；并发修改提示刷新重试，批量操作全成功或全失败。范围变更写入事项操作记录；批量编排会通知事项的负责人和参与人（不通知操作人）。

本版参考 [Atlassian 的 Sprint Planning](https://www.atlassian.com/agile/scrum/sprint-planning) 中的目标与范围组织方式，以及 [Linear Cycles](https://linear.app/docs/use-cycles) 的周期、归属和进度管理。采用按事项数量计算进度；尚未加入工作量估算、历史燃尽图或自动结转。

## 访客演示

分享链接：<https://celiawang.fun/youke>。这是同一域名下的路径，无需新增 DNS 记录或证书。支持直接分享详情链接，例如 `/youke#/iterations/demo-current`。

访客无需账号，浏览独立的 7 条需求、10 条任务和 3 个迭代，以及虚构成员、平台、字典、通知。可搜索、筛选、切换看板和查看详情；创建、编辑、删除、排序、上传、标记通知已读与 AI 助手关闭。刷新重新生成演示数据，不保存访客操作。

演示数据由前端独立构造，不读取登录会话或真实工作区，不将真实数据复制进演示库。即使已登录正式系统，访问 `/youke` 也只展示样例；所有业务 API 维持原有身份和权限校验。页面顶部明确标记“访客 · 只读演示”，可返回正式登录入口。

## 验证

前端测试覆盖公开路径匹配、数据独立性及关联完整性。云 MySQL 集成测试使用独立随机测试库，覆盖迭代生命周期、权限、有效日期、批量原子回滚、版本冲突、跨迭代移动、正常表单归属变更及删除后保留事项；不向真实工作区写入验收数据。
