# 产品工作台部署说明

## 当前状态

前端、后端及云 MySQL 已贯通，当前运行在本机。线上入口规划为 `https://workbench.celiawang.top`，云服务器为 `124.221.118.122`。

上传配置提供的是 `mysql-tunnel` 的 SSH 隧道权限，不包含 Shell、软件安装或部署权限。因此本轮未在云服务器安装 Node、Nginx、证书、系统服务，也未修改 DNS 或防火墙。不能将数据库连接成功等同于网站已经发布。

## 服务器准备

需要拥有服务器部署权限的账号执行以下操作：

1. 安装 Node.js 24 LTS 与 Nginx；创建无登录权限的 `workbench` 系统用户。
2. 将源码和已构建的 `dist/` 放到 `/opt/product-workbench`。不要传入本机 `.env`、`.runtime`、SSH 私钥、测试账号或 `node_modules`。
3. 在 `/opt/product-workbench/server` 执行 `npm ci --omit=dev`。
4. 创建 `/var/lib/product-workbench` 并归 `workbench` 用户所有。
5. 根据 `deploy/production.env.example` 创建 `/etc/product-workbench.env`，以 `workbench` 用户可读、其他用户不可读的权限保存。将 MySQL 密码单独放在 `/etc/product-workbench/mysql_password.txt`，权限同样收紧。云上进程直接访问服务器本机 MySQL 的 3306 端口，不需要 SSH 隧道。
6. 安装 `deploy/product-workbench.service` 到 systemd。核对 Node 路径后执行 `systemctl daemon-reload` 与 `systemctl enable --now product-workbench`。
7. 将子域名 A 记录指向云 IP，核实域名备案及服务商接入要求，开放 80/443，仅允许数据库本地访问。
8. 申请 HTTPS 证书，将证书真实路径填写到 `deploy/nginx.conf`，执行 `nginx -t` 后加载配置。

首次管理员临时密码只在空数据库初始化时生成；当前云库已初始化，线上进程不会覆盖已有密码或业务数据。本机初始化密码需要通过私密渠道交给管理员，首次登录由管理员自行改密。

## 验收

检查 HTTPS 页面、登录及首次改密、创建需求和关联任务、多人分派、描述图片与附件、权限拒绝、通知已读、刷新持久化、拖拽排序、归档恢复、删除、手机布局。确认不登录无法访问 `/api/workspace` 与附件。

健康接口为 `/api/health`。后端只监听 `127.0.0.1:3001`，Nginx 转发前端与 API，避免将应用端口或 MySQL 直接暴露公网。登录 Cookie 使用 HttpOnly、SameSite 与生产环境 Secure；跨站写请求同时检查 Origin 与 CSRF。

## 备份和运行

业务数据及附件都存储在 `friend_product_workbench` 中，必须备份整个库，定期验证恢复，备份文件加密并限制访问。备份、告警、证书续期和灾备演练需要在具备服务器权限后配置，当前尚未启用。

所有时间采用 Asia/Shanghai。提醒在后端启动时及每小时扫描，覆盖到期前 3 天、当天和逾期，按事项、成员、日期去重。服务停机期间不会发送提醒，重启后补扫描当前状态。

## 已知边界

- 当前团队前端通过 `/api/workspace` 拉取团队快照，表格在前端筛选分页；独立的服务端筛选分页接口已提供。数据规模增大时应将列表切到该分页接口。
- 单个附件限制 1 MB，图片与普通附件各最多 12 个，未保存附件 24 小时清理。大型文件和高并发附件场景后续改接私有对象存储。
- 删除事项为逻辑删除，操作及安全审计保留，界面不提供恢复已删除事项。基础数据被历史事项引用时请停用，不允许强制删除。
- 尚未配置邮件、短信、外部推送、自动备份及在线部署流水线。
