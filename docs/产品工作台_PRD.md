# 产品工作台 PRD

更新日期：2026-10-09。本文描述当前实现的功能，不包含初期备选方案。

## 1. 产品范围

面向产品、研发和测试团队，统一管理需求、任务、分派、时间节点和站内提醒。PC 优先，适配移动浏览器。前后端分离，真实业务数据存储在云 MySQL。

线上域名：`https://dylandw.site`，部署于腾讯云服务器。GitHub 为代码托管仓库，不是业务网站。

## 2. 导航和工作台

一级菜单：工作台、需求池、任务管理、通知中心、基础管理。基础管理下包含平台管理、人员管理、字典设置，仅管理员可管理。

面包屑与侧栏层级一致：一级页面显示当前模块；基础管理页面显示“基础管理 › 当前页面”；事项详情显示所属模块和事项名称，模块链接可返回列表。

工作台包含：

- 重点关注需求：总数及待评估、设计中、研发中、测试中、已上线的数量，环形图与状态图例联动高亮，可跳转对应列表。
- 重点关注任务：总数及待开始、进行中、阻塞、已完成、挂起的数量。“待开始”对应任务状态“待处理”。
- 混合事项列表：重点关注、我负责的、我参与的三个页签，个人页签在重点关注范围内筛选。需求与任务通过“类型”列区分，负责人和截止时间独立成列，不展示关注原因。
- 临期与逾期：以需求目标上线日期或任务最终截止日期为准，统计已逾期或今天至未来 3 天内的未完成事项，随左侧列表高度延展，超出可容纳数量时分页。

不包含“全部事项”页签或“本周交付”统计区。

## 3. 账号和权限

岗位角色为产品、研发、测试；操作权限为管理员、普通成员，二者独立。

- 管理员创建账号，系统生成临时密码；首次登录及重置密码后必须改密。
- 密码长度为 12 至 128 位，至少包含字母和数字；密码安全哈希存储。
- 停用账号不能登录，不能新增分派；历史分派可以保留。
- 团队成员可查看需求和任务、创建事项。
- 管理员、创建人、负责人可编辑事项基础信息及分派。
- 参与人可更新状态、备注、附件及里程碑完成状态，不可修改基础信息和分派。
- 归档、恢复、删除事项以及基础管理操作仅管理员可执行。
- 当前账号及最后一位启用管理员不能删除或停用；密码重置撤销原会话。
- 通知只向所属成员展示；草稿附件仅上传人可见，绑定事项后团队可见。

## 4. 需求和任务

需求池及任务管理支持表格、状态看板、分页、关键字搜索、字段排序、详情、新建、编辑、删除和归档查询。

筛选条件：状态多选、平台、优先级、负责人、参与人、重点关注是/否；关键字可匹配名称、编号及描述。重点关注仅采用手动开关，不提供关注来源筛选。

公共字段：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 平台 | 是 | 选择启用平台 |
| 名称 | 是 | 需求名称或事项名称 |
| 描述 | 否 | 文本，可粘贴图片并预览 |
| 状态 | 是 | 需求和任务分别使用固定状态 |
| 优先级 | 是 | P1-P4 |
| 来源 | 否 | 从相应字典选择 |
| 重点关注 | 否 | 手动开关，默认否 |
| 负责人 | 是 | 一个负责人 |
| 参与人 | 否 | 多个参与人，排除重复及负责人 |
| 备注 | 否 | 补充说明 |
| 描述图片、附件 | 否 | 上传、预览、下载、移除 |
| 编号、创建人、创建和更新时间 | 系统 | 编号只读，时间显示北京时间及年份 |

需求附加字段：需求类型、提出人、提出时间、目标上线时间、实际上线时间。需求类型和来源由管理员维护；实际上线时间由后端维护。

任务附加字段：关联需求、开始时间、最终截止时间、实际完成时间、多个里程碑。每个里程碑包含名称、计划时间、完成状态和实际完成时间；名称及计划时间必填。最终截止时间不能早于开始时间。

编号为全局递增的 `R00001`、`T00001`，不可修改，删除后不复用。

优先级：P1 重要紧急，P2 重要不紧急，P3 不重要紧急，P4 不重要不紧急。

需求状态：待评估、设计中、研发中、测试中、已上线。

任务状态：待处理、进行中、阻塞、已完成、挂起。

状态颜色在工作台环形图、图例及各页面状态标签中保持一致：

| 状态 | 颜色 | 色号 |
| --- | --- | --- |
| 待评估、待开始（待处理） | 灰色 | `#8993A5` |
| 设计中、进行中 | 紫色 | `#8A6BD1` |
| 研发中 | 蓝色 | `#3F73E6` |
| 测试中 | 青色 | `#238FAB` |
| 已上线、已完成 | 绿色 | `#279C74` |
| 阻塞 | 红色 | `#D94F63` |
| 挂起 | 橙色 | `#C88719` |

允许状态跳转及退回。上线和完成时间由后端自动记录；重新打开事项时清空当前完成时间，历史记录保留。必填字段在表单标签左侧显示红色星号。

一条需求可关联多个任务，一个任务最多关联一条需求，也可独立存在。从需求详情新建任务可带入需求及平台。删除需求时保留任务并解除关联。

需求列表显示“关联任务数”，统计未归档的关联任务；点击数字进入仅显示该需求关联任务的任务列表。任务列表显示“关联需求数”（0 或 1），有关联时点击数字进入需求详情。任务列表的“更多筛选”提供关联需求条件，跳转后展开并显示已选条件。操作列保持固定，移动端也显示关联数量。

## 5. 重点关注和提醒

时区为 Asia/Shanghai，本周从周一至周日。

关注相关标题、筛选字段和表单统一显示“重点关注”。只采用手动关注，持续生效直到人工取消；时间节点不自动纳入重点关注。

手动纳入：开启重点关注后，工作台及详情显示“重点关注”，直到人工取消。

需求及任务列表的“重点关注”列提供手动关注开关，点击直接保存，PC 表格和移动端列表均支持。管理员、创建人和负责人可操作；无编辑权限及已归档事项的开关禁用。保存时显示加载状态，失败保留原状态并提示原因。

归档事项不计入工作台重点。临期与逾期独立计算，取消手动关注不停止时间提醒。

需求池及任务管理的表格分别展示负责人、参与人，移动端列表也显示两种分派关系。支持关键词、多个状态、平台、负责人、参与人及重点关注筛选；优先级和关联需求默认折叠在“更多筛选”中。折叠不清空已选条件，按钮显示已启用的次要筛选数量，重置清空全部条件。筛选输入框及单选、多选框统一为 36px 高度，并随屏幕宽度换行。

需求及任务列表默认依次按编号降序、优先级 P1 至 P4、状态从早到晚、手动关注在前排序；编号不同优先比较编号。日期为空只展示“—”，完成事项仅展示日期，未完成且有日期时保留倒计时或逾期提示。

工作台混合列表的时间列标题为“截止时间”，使用需求的目标上线时间或任务的最终截止时间，表格仅展示完整日期，字体与其他列一致，移动端同样使用“截止时间”。

临期列表显示未来 3 天内到期及已经逾期的未完成事项；按时间先后排列，今天、明天、逾期等文案与完整日期配合展示。挂起任务暂停自动临期及逾期提醒，阻塞任务不暂停。

描述编辑区域使用统一边框容纳文字与图片。粘贴、拖放或选择图片后，在描述框内显示大图，可放大、下载和移除；详情页使用同样的边框与大图展示。已有文字描述、描述图片和附件继续兼容，普通附件仍单独展示。

分派、事项信息变更及里程碑完成状态变化生成站内通知。后端启动及每小时扫描到期前 3 天、到期当天和逾期提醒；按事项、成员、日期去重。支持全部、未读、单条已读、全部已读及跳转详情。

通知中心标题旁提供小问号，支持鼠标悬浮、键盘聚焦及点击查看通知的接收人、触发时间、去重和停止条件，文案与后端共用规则常量。

右下角提供 AI 助手，支持自然语言批量创建需求或任务，必要信息不全时追问。默认负责人为当前成员、优先级 P2、初始状态待评估/待处理，每次最多 10 条；支持同批创建需求及关联任务。仅管理员可配置模型服务和 API Key。具体接入、权限及重试去重规则见《AI助手.md》。

## 6. 基础管理

- 平台：名称、说明、启用状态；名称必填且不可重复，支持新增、编辑、删除和拖拽排序。
- 人员：姓名、登录用户名、岗位、操作权限、启用状态；支持管理员创建、编辑、删除及重置密码，用户名创建后不可修改。
- 字典：需求类型、需求来源、任务来源；包含名称、启用状态，各分类独立拖拽排序。
- 被历史事项引用的基础记录不得强制删除，可停用；停用项不供新事项选择，历史值保留。

管理表格占满可用内容区域，操作按钮不被截断；移动端表格可横向滚动。

## 7. 数据和安全

- 事项删除为逻辑删除，历史操作与审计保留；不提供恢复已删除事项的界面。归档事项可以恢复。
- 事项修改记录操作人、时间及字段变化；安全审计仅管理员可访问。
- 并发编辑使用版本号检查，冲突提示刷新后重试，不静默覆盖。
- 描述图片及附件保存在 MySQL，单文件最多 1 MB，描述图片及普通附件各最多 12 个。未保存的草稿附件 24 小时后清理。
- 图片根据文件内容校验类型，HTML/SVG 不作为内联图片展示。
- 使用 HttpOnly 会话 Cookie、CSRF 和 Origin 校验；生产环境 Cookie 启用 Secure。凭据、私钥和临时密码不提交 Git。
- 直接打开打包 HTML 为离线演示模式，与真实账号和云数据隔离，不自动导入演示数据。

## 8. 当前边界

未包含原生 App、开放注册、多租户、即时聊天、邮件/短信/外部推送、批量导入导出及复杂报表。

当前前端读取团队快照并在前端筛选分页；后端分页接口已提供。自动备份、证书续期、线上告警和部署流水线尚未配置。现有 SSH 账号只提供 MySQL 隧道权限，线上部署需要具有 Shell 和服务管理权限的账号。

接口约定见 [API](API.md)，运行和上线步骤见 [部署说明](部署说明.md)。
